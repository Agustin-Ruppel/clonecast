# Clonecast v0.3 — Real Flow Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development if same session) to execute task-by-task.

**Goal:** Fix Clonecast's primary flow so it actually matches the user's real use case: paste a guion → pick a HeyGen avatar (out of 80-90 with search) → AI plans which parts are avatar vs B-roll → per-shot pick B-roll mode and caption style → render with avatar's native voice + Higgsfield B-rolls + optional Suno music + Hyperframes stitching.

**Tech stack:** No new deps for Sprint L. Sprint M adds Suno HTTP integration. Sprint N may add `ffmpeg` audio mixing helpers (already installed).

## Sprint L — AvatarPicker scale + native voice

**Goal:** A user with 80-90 avatars in HeyGen can find and pick one in under 10 seconds. The picked avatar's native voice is used by default (no ElevenLabs round-trip).

### Task L1: AvatarPicker — search, filter, recent, density

**Files:**
- Modify: `components/AvatarPicker.tsx`
- Test: `tests/unit/components/AvatarPicker.test.tsx` (extend existing)

**Changes:**
- Always-visible search input at top of the grid (filters by `name` case-insensitive, debounced 200ms).
- Filter chips below search: `Todos | Hombres | Mujeres | Recientes` — `gender` from API, `Recientes` reads from localStorage `clonecast:avatar:recent` (max 8).
- Picking an avatar pushes its id to the recent stack.
- Grid: `grid-cols-4 sm:grid-cols-6 md:grid-cols-8` (denser than current 3/4/6). Card size ~120px wide. Aspect ratio of preview image preserved.
- When `avatars.length > 20`, the grid is `max-h-[500px] overflow-y-auto`. Scrollbar styled subtly.
- Selected avatar shows `default_voice_id` info: small "Voz nativa: <name>" pill below the grid (after picking). Requires API response to include voice info — see L2.
- Loading skeleton: 16 cards.
- Empty state, error state, refresh button stay as-is.

**Steps:**
1. Write test: render with 30 mock avatars, type "leo" in search → only Leo shows. (Or skip if too brittle.)
2. Implement search + filter + recent.
3. Implement denser grid + scroll container.
4. Implement "Voz nativa" pill.
5. Run vitest, typecheck, build.
6. Commit: `feat(avatar-picker): search, gender/recent filters, dense grid, scroll for 80+ avatars`.

### Task M2: HeyGen templates as alternate entry

**Files:**
- Create: `app/api/heygen/templates/route.ts` — `GET` returns `{ templates: { id, name, thumbnail_url, aspect_ratio }[] }`. Cached 24h in `avatars_cache` table (rename to `provider_cache` if needed, or new table).
- Create: `components/generate-v2/TemplatePicker.tsx` — grid of templates with thumbnails, click selects.
- Modify: `components/generate-v2/WriteStep.tsx` — add second mode tab "Usar template HeyGen" at top.

- On submit, POST `/v2/template/{id}/generate` and treat the returned video_id as a special-case job (skip the planner; render is the template itself)

**Steps:** 1) endpoint, 2) component, 3) integrate into WriteStep, 4) commit `feat(heygen-templates): use HeyGen templates as alternate generate path`.

### Task M3: Webhook receiver + polling fallback

**Files:**
- Create: `app/api/heygen/webhook/route.ts` — `POST` receives HeyGen events `{event_type, event_data: {video_id, url, status}}`, updates the job row in DB, returns 200.
- Modify: `lib/providers/heygen.ts` — `createAvatarVideo()` accepts optional `callback_url`. When provided (production), send it. When not (local dev), pipeline falls to polling.
- Modify: `lib/pipeline/run.ts` — if `process.env.CLONECAST_PUBLIC_URL` is set, use it for `callback_url`. Otherwise poll.
- Polling implementation: exponential backoff (2s, 4s, 8s, 16s, 30s, 30s...), respects `Retry-After` on 429, max 10 minutes.

**Steps:** 1) webhook route, 2) provider option, 3) pipeline branching, 4) test polling backoff, 5) commit `feat(heygen): webhook receiver + exponential-backoff polling fallback`.

### Task M4: Move to v3 endpoints

**Files:**
- Modify: `lib/providers/heygen.ts` — switch creating/polling to `v3/video/generate` and `v3/video/status`. The v2 endpoints stay supported until Oct 2026 but new capabilities are v3-only.

**Steps:** 1) switch endpoints, 2) handle response shape diffs, 3) test mock-mode, 4) commit `refactor(heygen): migrate to v3 API endpoints`.

## Sprint N — Suno music + Hyperframes multi-track stitching

**Goal:** Optional background music via Suno. Hyperframes composer produces a real multi-track timeline (video clips back-to-back, voice audio embedded, music underneath, captions on top).

### Task N1: Suno provider

**Files:**
- Create: `lib/providers/suno.ts` — `generateMusic(opts: { prompt: string; durationSec: number }): Promise<{ url: string }>` with mock that returns a placeholder MP3 path.
- Modify: `.env.example` — add `SUNO_API_KEY=`.
- Modify: `lib/types.ts` `ProviderKeys` — add `SUNO_API_KEY`.
- Modify: `app/api/keys/validate/route.ts` validators — add Suno key validator (ping endpoint).

**Steps:** 1) provider, 2) types + env, 3) validator, 4) test mock, 5) commit `feat(suno): TTS music generation provider`.

### Task N2: Music picker UI

**Files:**
- Create: `components/generate-v2/MusicPicker.tsx` — section at the bottom of PlanStep:
  - Toggle "Música de fondo" off by default
  - When on: 5 quick presets (Lo-fi calm, Cinematic build, Energetic, Acoustic warm, Custom prompt)
  - Custom prompt = textarea
  - Volume slider 0-100% (default 30% / -10dB)
  - Generates a 30s sample on click "Preview" (calls Suno)
- Modify: `app/api/generate/route.ts` — accept optional `music: { prompt?: string; preset?: string; volume?: number }` in the body.
- Modify: `lib/pipeline/run.ts` — when music is requested, await Suno generation, pass URL to composeHTML.

**Steps:** 1) component, 2) wire to generate route, 3) test, 4) commit `feat(music): MusicPicker with Suno-backed presets`.

### Task N3: Hyperframes timeline — multi-track

**Files:**
- Modify: `lib/composition/types.ts` — `buildComposition()` now emits a proper timeline:
  - Video tracks: each shot is a `<video>` with `data-start = cumulative_offset`, `data-duration = shot.duration_sec`. Avatar clips keep their embedded audio; B-roll clips muted (set `muted` attribute).
  - Music track: if `brand.music_url`, emit a `<audio data-start="0" data-duration="${total_duration}" src=...>` element with CSS or attr for volume (Hyperframes producer respects audio volume).
  - Captions: per-word `<span class="cap cap--<style>" data-start data-duration>` on top.
- Verify the producer mixes audio correctly: avatar's voice + music at lower volume = final audio track. May require an explicit `data-volume="0.3"` attribute on the music `<audio>` if Hyperframes supports it; otherwise post-process with ffmpeg.

**Steps:** 1) emit proper timeline HTML, 2) test composition output by inspection, 3) end-to-end mock render, 4) commit `feat(composition): proper multi-track timeline (video back-to-back + music + captions)`.

### Task N4: ffmpeg fallback for audio mixing

**Files:**
- Create: `workers/audio-mixer.py` (or use ffmpeg directly via execa) — if Hyperframes doesn't respect audio volume per-track, post-process the rendered MP4 with ffmpeg to attenuate the music track.
- Modify: `lib/pipeline/run.ts` render step — after `renderVideo()`, if music was used, run the mixer.

Only ship this if N3 testing reveals Hyperframes can't mix at the right levels.

**Steps:** 1) verify N3 first, 2) implement only if needed, 3) commit `chore(audio): ffmpeg post-mix for music volume`.

**Sprint N ETA:** 4 commits. ~4 hours subagent work.

## Risk assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| 80-90 avatars makes mock-mode response huge | Low | Low | Mock returns 6, real-mode is the only path that hits the API |
| Higgsfield modes have different params we don't yet know | Medium | Medium | Implement what docs show; for unknown modes, log and fallback to Photodump |
| HeyGen v3 response shape differs from v2 silently | Medium | High | Snapshot test of mock v3 response; type-safe parsing with zod |
| Webhook needs public URL; dev workflow breaks | High | Low | Polling fallback shipped together. Public URL via env var only. |
| Suno API rate limits / cost overruns | Medium | Low | Default OFF. Estimate panel shows music cost. |
| Hyperframes producer audio mixing doesn't respect volume | Medium | Medium | N4 ffmpeg post-mix as safety net |
| User's avatar fetch times out at 80+ avatars | Low | Low | 24h cache, refresh only on user action |
